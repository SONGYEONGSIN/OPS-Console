# 주간업무보고 목록 화면 정리 (1차) — 짧은 설계

- 작성: 2026-11-21 · 상태: 사용자 지시로 확정(대화)
- 앞선 설계: `2026-11-19-ops-weekly-role-layout-design.md`

## 왜
사용자 지시(2026-11-21): 관리 탭의 고르는 상자·체크박스를 조직·권한 목록처럼 **표 + 행 버튼**으로, 제출 현황을 기본 목록 모양으로, 원서접수 목록을 표로(대학구분·카테고리 추가), 상단 카드 너비를 균등하게.

## 무엇
1. 관리 탭 — 당번 지정·받는 사람·당번 순번·작성 제외를 공통 `RosterTable`(이름·팀·이메일 + 행 끝 칸)로. 메뉴 이름 `당번 순번` · `프로젝트·TF` · `지정 안된 서비스`, `작성 제외`는 `지정 안된 서비스` 바로 위.
2. 받는 사람 후보 = 운영1·2팀 활성 전원(부장·팀장 포함). 작성 명단(부장·팀장 제외)에서 고르면 정작 받을 사람이 없다. 명단 밖 주소는 표 맨 위 행 + 아래 이메일 직접 입력.
3. 제출 현황 — 기본 목록 제목(`제목 · 제출 n / m명`, vermilion), `미제출: …` 줄 삭제(표 상태 칸이 보여 준다). 머리띠의 `제출 n/m · 당번`은 내 보고서에서만.
4. 상단 카드 — lg 5열, 다섯 장 같은 너비(차주 오픈/마감은 한 장 안에 두 칸). 폰·태블릿 3열은 그대로.
5. 원서접수 목록 — 표(대학명·대학구분·카테고리·서비스명·오픈|마감·메모). `closing_services.university_type`·`category`를 자동 항목에 싣는다. 스냅샷 스키마는 두 칸을 optional 로 받아 예전에 굳힌 값도 통과하고 빈칸은 `—`.

## 접근
- 고른 것: 공통 표 하나(`RosterTable`)를 네 칸이 같이 쓴다 — 같은 모양이 넷이라 공통 컴포넌트 규칙(3회+)에 해당.
- 버린 것: `ListPattern` 재사용 — 인스펙터·필터가 딸려 와 관리 칸 안에 넣기에 과하다.

## 하지 않는 것
- 합격자 발표·휴가 탭의 목록 모양(그대로 목록).
- '내 보고 / 전체 보고' 토글 — 2차.
