# 주간업무보고 역할별 화면 개편 — 설계

- 작성: 2026-11-19
- 상태: 사용자 답 반영(2026-11-19) — 승인 대기
- 시안(캔버스): https://claude.ai/artifact/1p6eXNgkBznCVLbqx1QBnT — '2차 · 역할별 시안' 페이지의 **시안 1 · 확인|작성 2단**, **당번 화면(공통)**, **관리자 화면(공통)**
- 앞선 설계: `docs/superpowers/specs/2026-11-16-ops-weekly-report-design.md`(A1), #1265(하위 탭·KPI 고정)

## 1. 왜

사용자 요청(2026-11-18): 운영자가 **볼 것**과 **쓸 것**, **당번**이 할 것, **관리자만** 볼 것을 갈라서 화면을 짠다.

지금 화면은 탭 일곱 개(원서접수·PIMS·프로젝트·TF·휴가·외근·제출 현황·설정)가 한 줄로 놓여 있다.

- 볼 것(자동 목록)과 쓸 것(특이사항·직접 추가·프로젝트 진행)이 탭마다 본문 안에 섞여 있다.
- 제출 현황 탭은 모두에게 보이고, 그 머리에 관리자 버튼(당번 바꾸기·정정)이 있다.
- 설정 탭은 패널 다섯 개가 세로로 쌓여 있다.
- 일반 운영자도 주소(`?op=`)를 바꾸면 남의 보고서를 읽을 수 있다.

#1265 가 '스크롤이 너무 길다'를 하위 탭으로 줄였다. 이번에는 역할로 가른다. 시안 넷 중 사용자가 시안 1(왼쪽 자동 목록 읽기 | 오른쪽 쓸 칸 패널)을 골랐고, 프로젝트·TF 는 넓은 서랍에서 쓰기로 했다.

## 2. 목표

1. 역할 탭 셋 — **내 보고서**(작성자) · **제출 현황**(그 주 당번·관리자, 받는 사람은 읽기 전용) · **관리**(관리자).
2. 내 보고서는 lg 이상에서 두 칸이다. 왼쪽은 **볼 것**(자동 목록), 오른쪽은 **쓸 것**(스크롤을 따라오는 패널).
3. 프로젝트·TF 는 패널의 요약 카드에서 [쓰기]를 눌러 **넓은 서랍**에서 쓴다.
4. 제출 현황은 지금 탭에서 관리자 버튼만 뺀 것이다.
5. 관리는 시스템 설정과 같은 꼴(왼쪽 메뉴 + 오른쪽 내용)이고, 여러 주를 한눈에 보는 **전체 현황**을 새로 둔다.
6. 남의 보고서는 그 주 당번과 관리자가 열고, 받는 사람은 보고가 끝난 주를 읽기만 한다. 권한 없는 탭·보고서의 데이터는 서버가 읽지도 넘기지도 않는다. 이것은 화면 정리이지 보안 경계가 아니다(6.7).
7. 좁은 화면(lg 미만)은 두 칸을 쌓지 않고 [목록 | 쓰기]로 바꿔 본다.

## 3. 하지 않는 것

- DB 스키마와 읽기 정책(RLS)은 그대로다. 마이그레이션이 없다.
- 저장·제출·다시 작성 요청·최종 보고·굳히기·정정의 동작은 그대로다. 확인 토글도 그대로다(영역 다섯 개 단위, 추가만, 제출을 막지 않는다).
- 편집 권한(`canEditReport` 등 `permissions.ts` 의 편집 판정)은 그대로다. 바뀌는 것은 **열람**과 **탭 노출**뿐이다.
- 당번 화면 시안의 '운영부 전체 모아보기'(합계)는 만들지 않는다. 지금 코드에 없고, 뺀 건을 넣을지부터 정해야 한다 — 본부보고(B) 때 한다.
- 머리띠의 제출 마감 표시는 넣지 않는다 — A2 가 넣는다(6.2, 7).
- 발송(A2)·엑셀/워드(A3)는 이 일과 별개다.
- 시스템 설정(`SettingsClient`)과 `SettingsPattern` 을 새 공통 컴포넌트로 옮기지 않는다.

## 4. 동작해도 실패로 치는 것

- 영역을 바꾸거나, 서랍을 여닫거나, [목록 | 쓰기]를 바꿨을 때 입력이나 저장 대기 중인 값이 사라진다. #1265 는 비활성 패널을 `hidden` 으로 마운트해 두는 방식으로 이를 막았다.
- 일반 운영자가 주소를 손으로 바꿔 제출 현황·관리·남의 보고서를 본다. 탭만 숨기고 서버가 그 데이터를 읽어 화면(RSC 응답)에 실어 보내는 것도 실패다.
- 받는 사람이 보고되지 않은 주를 보거나, 읽기 전용 화면에서 버튼(다시 작성 요청·총평 편집·최종 보고)을 본다.
- 볼 수 있는 화면이 하나도 없는 사람이 빈 화면이나 남의 보고서를 본다. 안내 화면을 보여야 한다.
- 관리자 버튼(정정·당번 바꾸기)이 관리 탭 밖에 남는다.
- 쓸 것 패널이 화면보다 길어 아래쪽(제출 버튼)에 닿지 못한다.
- 기존 주소(`?tab=application&sub=…`, `?tab=status`, `?tab=settings`, KPI 카드 링크)가 엉뚱한 곳에 떨어진다.
- 좁은 화면에서 두 칸이 위아래로 쌓여 스크롤이 다시 길어진다.
- 제출 버튼이 두 곳에 있다. 시안 1 은 머리띠와 패널 양쪽에 그렸지만 하나만 둔다.

## 5. 제약

- Next.js 16 App Router. 하위 탭은 `history.replaceState` 로 바꾸므로 서버를 안 다녀온다. 이동 중에 `replaceState` 가 불리면 그 이동이 취소되는 Next 16 동작이 있다(CLAUDE.md).
- 대시보드 셸의 content div 가 스크롤 컨테이너이고 sticky 를 그 안에 가둔다(CLAUDE.md, #1265). KPI 줄과 쓸 것 패널이 같은 컨테이너에서 둘 다 sticky 라서, 패널의 top 은 `--ops-kpi-h` 만큼 비켜 서야 하고 높이도 그만큼 빼야 한다.
- 받는 사람 명단 표(`ops_weekly_recipients`)의 select 정책은 관리자 전용이다(`supabase/migrations/20261116_ops_weekly.sql`). 관리자가 아닌 사람의 세션으로는 명단을 못 읽는다. 그래서 '나는 받는 사람인가'는 서버에서 service role(`src/lib/supabase/admin`)로 본인 하나만 대조한다. 명단은 화면에 내려보내지 않는다.
- 디자인 표준(CLAUDE.md Design System)을 따른다.
  - 목록·메뉴 항목: 호버 `hover:bg-line-soft`, 선택 `border-vermilion bg-vermilion/10 text-vermilion`. 관리 왼쪽 메뉴와 영역 탭이 여기 든다.
  - 버튼 호버: `hover:bg-ink hover:text-cream`.
  - 표면 `bg-paper`, 카드 `bg-situation-bg`, 입력 `border-line-soft bg-field-bg`.
  - 숫자는 `tabular-nums`, 날짜는 `kstFormat`. 하드코딩 색은 금지다.
  - 시안의 남색·황토색·붉은 칸은 역할을 설명하려고 칠한 것이지 실제 색이 아니다.
- 라우트 가드는 지금처럼 `requireMenu("ops-weekly")` 하나다. 역할 판정은 `permissions.ts` 의 기존 판정(`isDuty`, 관리자 여부, `canManageSettings` 등)을 쓰고, 페이지가 권한 문자열을 따로 비교하지 않는다. 받는 사람 판정도 같은 곳에 둔다.
- 호환용 shim·폴백 금지(`.claude/rules/donts.md`). 그래서 주소 어휘를 바꾸지 않는다(6.6).
- 새 화면은 디자인 에이전트(designer·frontend-design-specialist)와 `/design-audit` 를 거치고, 390/768/1280 폭을 확인한다. UI 테스트는 문구만이 아니라 모양(클래스)까지 단언한다.
- 이 PC 는 메모리가 빠듯하다. vitest 는 디렉터리를 지정하고 `--maxWorkers=1` 로 돌리며, dev 서버와 `next build` 는 돌리지 않는다. CI 를 독립 검증으로 삼는다.

## 6. 정한 것

(사용자) = 사용자가 정한 것, (판단) = 설계자가 정한 것. (판단)은 승인 때 함께 확인받는다.

### 6.1 역할 탭

| 탭        | 보이는 사람                                                                                         | 내용 |
| --------- | --------------------------------------------------------------------------------------------------- | ---- |
| 내 보고서 | 작성 대상(명단에 있는 사람)                                                                         | 6.2  |
| 제출 현황 | 보는 주의 당번(`isDuty(actor, week)`)과 관리자. 받는 사람은 보고가 끝난 주에서만 읽기 전용으로 본다 | 6.4  |
| 관리      | 관리자                                                                                              | 6.5  |

- 탭이 하나뿐인 사람(일반 운영자)에게는 탭 줄을 그리지 않는다. (판단)
- 명단에 없는 관리자·당번·받는 사람은 내 보고서 탭이 없고, 처음 화면이 제출 현황이다. (판단)
- 볼 수 있는 화면이 없는 사람에게는 안내 화면을 보인다. (사용자) 예를 들면 다음과 같다.
  - 작성 대상도 당번도 관리자도 받는 사람도 아닌 사람
  - 보고되지 않은 주를 연 받는 사람
  - 자기 당번이 아닌 주를 연 명단 밖 당번
- 지금 '설정' 탭의 이름은 '관리'로 바꾼다. 설정 말고도 전체 현황·당번 지정·정정이 들어가기 때문이다. (판단)
- 누가 무엇을 보고 쓰는지는 확정된 분류를 따른다. (사용자)
  - 운영자가 볼 것: 원서접수(개발·테스트·운영 중·차주 오픈·마감), 합격자 발표(금주·차주), 휴가·외근 자동 목록, KPI 숫자, 내 상태
  - 운영자가 쓸 것: 줄 메모·빼기, 직접 추가, 특이사항 금주·차주, 프로젝트·TF 진행, 그림, 영역 확인, 제출
  - 당번(그 주만): 제출 현황, 다시 작성 요청, 당번 총평, 최종 보고
  - 관리자: 설정(받는 사람·순번표·작성 제외·프로젝트·TF 목록), 안 붙은 서비스, 당번 지정, 정정, 전체 보고서 보기·고치기(고치기는 정정으로 연 주에서만 — 6.5)
  - 받는 사람(2026-11-19 추가): 보고가 끝난 주의 제출 현황과 각 보고서를 읽기만 한다

### 6.2 내 보고서 (사용자: 시안 1)

위에서 아래로 놓인다.

1. **주 머리띠** — 주 이동은 세 탭이 같이 쓴다.
   - 내 보고서에서는 내 상태(작성 중·제출·다시 작성 요청)와 확인한 영역 `n/5` 를 더 보인다.
   - 제출 마감은 넣지 않는다. 지금 코드에 제출 기한 개념이 없고, 공휴일이면 당기는 규칙은 A2 의 `planSendDates` 가 만든다. A2 가 이 머리띠에 넣는다. (판단)
   - 제출 버튼은 여기 두지 않는다. 패널 한 곳에만 둔다. (판단)
2. **KPI 줄** — 지금 그대로다(#1265: lg 이상 고정, 카드가 하위 칸으로 링크). 내 보고서에서만 보이고 제출 현황·관리에서는 숨긴다. 작성자 한 사람의 숫자이기 때문이다. (판단)
3. **두 칸**(lg 이상)
   - 왼쪽 **볼 것**: 영역 탭 원서접수 / 합격자 발표 / 휴가·외근.
     - 원서접수·합격자 발표의 하위 칸(`?sub=`)은 #1265 그대로다.
     - 자동 목록 줄의 메모·빼기·되살리기와 직접 추가한 줄의 지우기는 줄 옆에 그대로 둔다. 그 줄에 붙은 조작이기 때문이다.
     - 확인한 영역은 지금처럼 영역 탭 이름 뒤에 ✓ 가 붙는다(프로젝트·TF 는 요약 카드에 표시).
     - 'PIMS' 탭 이름은 '합격자 발표'로 바꾼다. KPI 카드 이름과 맞춘다. (판단)
   - 오른쪽 **쓸 것** 패널: sticky 이고, 화면보다 길면 패널 안에서 스크롤한다. 순서는 다음과 같다.
     1. 왼쪽에서 고른 영역의 특이사항 금주·차주와 [이 영역 확인]. 특이사항이 왼쪽 영역을 따라 바뀐다. (판단) 다른 영역의 특이사항 칸도 마운트해 두고 `hidden` 으로 숨긴다.
     2. 직접 추가: 묶음 선택 + 입력. 묶음의 기본값은 지금 왼쪽에서 보는 하위 칸이다. 직접 추가가 있는 영역에서만 보인다. (판단)
     3. 프로젝트·TF 요약 카드 두 장 — 6.3
     4. 제출 버튼. 지금 `WeekHeader` 의 제출 동작·문구·저장 대기를 그대로 옮긴다.
4. **남의 보고서를 볼 때**(당번·관리자·받는 사람이 제출 현황에서 [보기]를 눌렀을 때) — 머리띠에 누구의 보고서인지와 돌아가는 링크가 보인다.
   - 고칠 수 있는지는 `canEditReport` 그대로다. 받는 사람이 여는 주는 보고가 끝난 주라 언제나 읽기 전용이다.
   - 남의 보고서에서는 제출 버튼이 없다.

### 6.3 프로젝트·TF 서랍 (사용자)

- 패널에는 프로젝트와 TF 요약 카드만 둔다. 예: '프로젝트 2건 · 1건 남음 [쓰기]'.
- [쓰기]를 누르면 오른쪽에서 넓은 서랍이 열린다. 서랍 안은 지금 `ProjectTab`(kind 별) 그대로다 — 진행 단계, 금주·차주, 그림 붙여넣기, 그 영역의 특이사항과 [이 영역 확인].
- 서랍은 표준 `InspectorPanel`(`src/app/dashboard/_components/inspector/InspectorPanel.tsx`)을 `widthClassName` 으로 넓혀 쓰는 것을 기본안으로 본다. 닫힌 서랍의 내용이 마운트돼 있어야 저장 대기가 산다. 이 셸이 그렇게 동작하는지 확인하고 쓴다.
- 카드의 '남음'을 무엇으로 셀지(금주 칸이 빈 항목 수 등)는 빌더가 정한다.

### 6.4 제출 현황 (사용자: 분류 + 당번 화면 시안)

- 지금 `StatusTab` 의 내용 그대로다 — 제출 수, 작성자 표([보기]·[다시 작성 요청]), 당번 총평, 프로젝트 모아보기, 최종 보고.
- `DutyPicker`(당번 바꾸기)와 [정정]은 관리 탭으로 옮긴다.
- 최종 보고 아래의 '당번 또는 관리자만 보고할 수 있습니다' 안내는 뺀다. 이 탭에서 버튼을 누를 수 있는 사람은 이제 당번·관리자뿐이고, 받는 사람은 보고가 끝난 주만 보므로 최종 보고 버튼이 나오지 않는다. 버튼 동작은 그대로다.
- 받는 사람에게는 같은 내용을 읽기 전용으로 보인다. [다시 작성 요청]·총평 편집·최종 보고가 없다. (사용자)
- 다시 작성 요청 사유는 지금처럼 선택 입력이다(`return_reason`, 1,000자). 시안의 '사유 (필수)'는 따르지 않는다. (판단)
- 일반 운영자는 이 탭이 없어서 프로젝트 모아보기도 볼 수 없게 된다. 분류대로이며 사용자에게 알렸다.

### 6.5 관리 (사용자: 시스템 설정형)

- 왼쪽 메뉴 + 오른쪽 내용. `SettingsClient` 와 같은 꼴이다: md 이상 `grid-cols-[240px_1fr]`, 선택은 `?section=`.
- 메뉴 순서: 전체 현황 / 당번 지정 / 받는 사람 / 당번 순번표 / 작성 제외 / 프로젝트·TF 목록 / 안 붙은 서비스(건수 배지).
- 기존 패널 다섯(`RecipientsPanel`, `RotationPanel`, `WriterExclusionPanel`, `ProjectCatalogPanel`, `UnmatchedServicesPanel`)은 내용을 그대로 옮긴다.
- 새로 만드는 것 둘:
  - **전체 현황**: 최근 주들의 표 — 주차, 기간, 상태(열림 / 보고 완료 시각 / 정정으로 열림), 제출 수, 당번, 작업.
    - 작업은 주 상태로 갈린다. 보고 완료 주는 [정정]과 [보기], 정정으로 연 주는 작성자별 보기·고치기, 보통의 열린 주는 작성자별 보기다.
    - 관리자는 정정으로 연 주에서만 남의 보고서를 고친다는 지금 규칙(`canEditReport`, CLAUDE.md) 그대로다. 관리자가 그 주 당번이면 당번으로서 고칠 수 있는 것도 지금 규칙이다. 관리자 화면 시안의 '열린 주에서만 남의 보고서를 고칠 수 있습니다' 문구는 틀렸으므로 따르지 않는다.
    - 주 상태는 `open|reported` 두 값이다. '정정으로 열림'은 `open` 이면서 `reopened_at` 이 있는 경우다.
    - 여러 주를 한 번에 읽는 쿼리는 지금 없어서 새로 만든다(`ops_weekly_weeks`, `ops_weekly_reports`).
    - 몇 주를 보일지와 제출 수 기준(열린 주는 지금 제출 현황과 같은 계산, 보고 완료 주는 그때 굳은 것)은 빌더가 실데이터로 정한다.
  - **당번 지정**: 열린 주의 당번을 바꾼다. 기존 `setWeekDuty` 와 `DutyPicker` 를 쓴다.
- 담당자 불일치 안내(`UnmatchedNotice`, 관리자만)의 링크는 관리 › 안 붙은 서비스로 바꾼다.
- 왼쪽 메뉴 레이아웃은 이번이 세 번째 복제다(`SettingsClient`, `SettingsPattern`). 디자인 규칙(3회 반복 시 추출)에 따라 `src/components/common/` 에 공통 컴포넌트로 뽑아 여기서 쓴다. 시스템 설정과 `SettingsPattern` 을 옮기는 것은 범위 밖이다. (판단)

### 6.6 주소 (판단)

어휘를 바꾸지 않는다. `?week=&tab=&op=&sub=` 그대로이고 `tab` 값도 그대로(application·pims·project·tf·leave·status·settings)다. 역할 탭은 `tab` 에서 나온다.

| `tab`                      | 화면                                             |
| -------------------------- | ------------------------------------------------ |
| application · pims · leave | 내 보고서 + 그 영역                              |
| project · tf               | 내 보고서 + 그 서랍이 열린 상태(왼쪽은 원서접수) |
| status                     | 제출 현황                                        |
| settings                   | 관리(+ `section=`)                               |

- 빈 값과 권한 없는 값은 그 사람의 처음 화면으로 돌린다 — 작성 대상이면 내 보고서 원서접수, 아니면 제출 현황, 그것도 볼 수 없으면 안내 화면이다. 지금 `parseTab` 이 관리자가 아닌 사람의 settings 를 다루는 방식을 status 에도 쓴다.
- 이렇게 하면 KPI 카드 링크(#1265)와 기존 북마크가 그대로 맞고 호환 코드가 필요 없다. 새 파라미터는 `section` 하나다.

### 6.7 열람 권한 (사용자: 분류 + 2026-11-19 답)

- 남의 보고서(`?op=`)를 여는 사람은 셋이다: 보는 주의 당번, 관리자, 보고가 끝난 주의 받는 사람. 그 밖의 사람은 `op` 를 무시하고 본인 보고서를 보며, 본인 보고서가 없으면 안내 화면을 본다. 판정하는 자리는 `pickViewed`(`_load.ts`)다.
- 권한 없는 사람에게는 제출 현황·관리의 데이터(작성자 표, 총평, 프로젝트 모아보기, 설정, 안 붙은 서비스, 전체 현황)를 서버에서 읽지 않는다. 실수로 화면에 새는 길을 막기 위해서다.
- **이 제한은 화면 정리다. 보안 경계가 아니다.** (사용자)
  - 주간보고 표의 DB 읽기 정책은 로그인한 사람 모두에게 열려 있다(`20261116_ops_weekly.sql` 의 select `using (true)`). 그래서 브라우저에서 DB 를 직접 조회하는 것까지는 막지 못한다.
  - 같은 부서의 업무 보고라 정책은 그대로 둔다. 이 한계를 CLAUDE.md ops-weekly 단락에 적는다.

### 6.8 좁은 화면 (판단)

- lg 미만에서는 두 칸 대신 [목록 | 쓰기] 전환 버튼을 둔다. 두 칸 모두 마운트하고 안 보이는 쪽은 `hidden` 이다.
- 서랍은 `InspectorPanel` 의 좁은 화면 동작(전체 폭 + 딤)을 그대로 쓴다.
- 관리 메뉴는 md 미만에서 위로 쌓인다(`SettingsClient` 와 같다).

## 7. 다른 작업과의 관계 (판단)

- 이 개편을 A2(작성 요청·미제출 알림 발송, 워크트리 `OPS-Console-feat-ops-weekly-a2`)보다 먼저 머지한다.
- A2 계획은 `opsWeeklyHref` 를 `features/ops-weekly/href.ts` 로 옮기는 등 `_params.ts` 를 고친다. 이 개편과 겹치므로 A2 를 시작할 때 이 구조에 맞춰 계획을 고친다.
- A2 의 링크 규칙(작성자 → application, 당번·받는 사람 → status, 관리자 경고 → settings)은 6.6 의 주소 어휘와 그대로 맞는다. 받는 사람에게 읽기 전용 열람을 준 까닭 중 하나가 이 링크가 열리게 하려는 것이다.
- 머리띠의 제출 마감은 A2 가 `planSendDates`(공휴일 당김 포함)를 만들 때 넣는다.

## 8. 빌더에게 맡기는 것

- 컴포넌트 경계·이름·파일 나누기(파일 800줄 상한).
- 패널 폭(시안은 360px)과 서랍 폭.
- 남의 보고서를 볼 때 탭 줄에서 어느 탭이 켜져 보이는지, 돌아가는 링크의 목적지.
- 안내 화면의 문구와 모양. 받는 사람이 보고되지 않은 주를 열었을 때 가장 최근 보고 주로 가는 링크를 줄지도 정한다.
- `tab=project|tf` 로 열린 서랍을 닫을 때 주소를 어떻게 남길지.
- 요약 카드의 '남음' 기준, 전체 현황의 주 수와 제출 수 계산.
- 테스트 갱신. 깨질 후보는 `StatusTab`, `WeekHeader`, `params`, `responsive`, `StickyKpiBar`, `page-subtabs`, `page-empty-roster`, `page-kpi-visibility`, 영역 탭 테스트(`ApplicationTab`·`PimsTab`·`LeaveTab`·`ProjectTab`·`AreaNotes`), `SettingsTab`, `permissions`, `UnmatchedNotice`, `UnmatchedServicesPanel` 이다. e2e 에는 ops-weekly spec 이 없다.
- CLAUDE.md 의 ops-weekly 단락 갱신(6.7 의 한계 포함).

## 9. 다 됐을 때의 모습

역할별로 확인한다.

- 일반 운영자: 탭 줄이 없고 내 보고서만 보인다. `?tab=status`, `?tab=settings`, `?op=남` 을 열어도 본인 내 보고서가 뜨고, 서버 응답에 남의 데이터가 없다.
- 그 주 당번: 내 보고서와 제출 현황이 보인다. [보기]로 남의 보고서를 연다(고칠 수 있는지는 지금 규칙). 당번이 아닌 주에서는 제출 현황이 없다.
- 관리자: 세 탭이 보이고 관리 메뉴가 일곱 개다. 정정과 당번 지정은 관리에서만 할 수 있다. 전체 현황의 작업 칸이 주 상태대로 갈린다.
- 받는 사람(관리자 아님): 보고가 끝난 주에서는 제출 현황과 [보기]가 읽기 전용으로 열리고 버튼이 없다. A2 메일 링크 모양(`?week=…&tab=status`)이 열린다. 보고되지 않은 주에서는 안내 화면을 본다.
- 아무 역할도 없는 메뉴 사용자: 안내 화면을 본다.

공통으로 확인한다.

- 영역 전환, 서랍 여닫기, [목록 | 쓰기] 전환 뒤에도 입력과 저장 대기가 남아 있다.
- 기존 주소와 KPI 카드 링크가 같은 자리로 간다.
- 390/768/1280 폭에서 깨지지 않고 `/design-audit` 를 통과한다.
