# 경쟁률 점검 실행 조건 창 — 설계

- 날짜: 2026-11-10
- 점검 본체: `docs/superpowers/specs/2026-08-02-moa-ratio-setting-audit-design.md`
- 구현 계획: `docs/superpowers/plans/2026-11-10-ratio-audit-run-filters.md`

## 1. 왜

자동화 페이지 '경쟁률 세팅 점검'·'경쟁률 페이지 점검'의 [지금 실행]은 누를 때마다 같은 범위를 본다. 서버 대상은 `closing_services.category = '수시'` 전부이고, 회사 PC 는 Moa 목록을 '올해 9월 1일 KST 이후 시작'(`scripts/moa-ratio/listfilter.py`)으로 거른다. 그래서 문제가 넷 생긴다.

1. **접수가 끝난 수시까지 매번 점검한다.** 11월이면 대상 대부분이 이미 지난 서비스인데, 약 17분과 알림이 거기에 쓰인다.
2. **정시는 아예 못 본다.** 대상이 `수시` 하나로 박혀 있다.
3. **1~2월에는 진행 중인 정시가 빠진다.** '올해 9월 1일'이 미래가 되어 12월에 시작한 서비스가 시작일 필터에서 떨어진다. 정시를 대상에 넣는 순간 드러나는 결함이다.
4. **사람이 '이번엔 무엇을 볼지' 고를 수 없다.** '4년제 수시만', '2년제 정시만' 같은 실행이 불가능하다.

## 2. 결정

### 사용자가 정한 것 (2026-11-10, 바꾸지 않는다)

| 항목 | 결정 |
|---|---|
| 조건 창 | [지금 실행]은 바로 적재하지 않고 조건 창을 연다. 세팅 점검(kind=schedule)과 페이지 점검(kind=page) 모두 같은 창을 쓴다 |
| 대학구분 | `4년제` / `2년제`(Moa 의 전문대·폴리텍·전공대학을 함께 부르는 이름). 하나 이상 골라야 한다 |
| 모집구분 | `수시`(값이 정확히 `수시`인 것만, `수시 재외국민` 제외) / `정시`(`정시`로 시작하는 값 전부 — `정시 가나다`·`정시 나` …). 하나 이상 골라야 한다 |
| 처음 상태 | 아무것도 안 고른 채 열린다. 두 묶음에서 각각 하나 이상 골라야 [실행]이 켜진다 |
| 기간 | 고정 — **접수 마감 전**(`closing_services.write_end_at >= 지금`). 진행 중과 오픈 예정이 여기에 든다 |

### 설계에서 정한 것

1. **조건은 요청 행에 적고, 폴러에는 요청 id 만 넘긴다.** `ratio_audit_requests.filters jsonb` 에 `{"univ":["2년제"],"recruit":["수시"]}` 처럼 적는다. 회사 PC 폴러는 claim 한 id 를 `RATIO_AUDIT_REQUEST_ID` 로 audit.py 에 넘기고, audit.py 는 `GET /api/ratio-audit/targets?requestId=` 로 대상을 받는다. 조건 해석·정시 접두 매칭·기간 비교는 서버의 한 파일(`features/ratio-audit/run-filters.ts`)과 대상 쿼리가 맡는다.
   - **조건을 쿼리 파라미터로 실어 나르는 길을 버린 이유:** 그 길에서는 값이 TS → PowerShell 5.1 → Python → TS 로 세 번 건넌다. 그런데 PS 5.1 의 `Invoke-RestMethod` 는 charset 이 없는 JSON 응답의 한글을 ISO-8859-1 로 읽어 깨뜨린다. 그렇다고 ASCII 코드로 바꿔 넘기면 Python 쪽에도 조건 어휘가 생겨, 서로 어긋나는지 지켜볼 곳이 하나 늘어난다. id 하나만 넘기면 Python 은 조건을 몰라도 된다.
   - **대가:** 손으로 돌리는 시험 실행(`RATIO_AUDIT_DRY_RUN`)에도 요청 id 가 필요하다. 이미 있는 요청의 id 를 쓴다. 대상 API 는 읽기만 하고 요청 상태를 따지지 않는다.
2. **Moa 목록 시작일 필터를 없앤다**(`listfilter.py` 삭제). 기간은 서버 대상이 이미 정한다. Moa 서비스ID 는 학년도마다 달라서, 교집합만으로도 지난 서비스가 빠진다. '시작일을 읽을 수 있는 행만 남기는' 필터로도 남기지 않는다 — 서버가 고른 대상을 Python 이 다시 빼면 그 대상은 아무도 모르게 사라진다.
3. **조건 없는 요청은 돌리지 않는다.** 마이그레이션은 적용 시점에 조건 없이 대기 중(pending)인 요청을 `failed`(사유: 실행 조건 도입 전 요청)로 마감한다. 그 뒤에 생긴 조건 없는 요청은 대상 API 가 409(`missing_filters`)로 거절하고, audit.py 는 **Moa 로그인 전에** 이유를 찍고 멈춘다(인증 문자가 가지 않는다). 기본 조건을 채워 돌리지 않는다 — '아무것도 안 고른 상태'가 기본값이기 때문이다.
4. **조건 없이 적재되는 길을 막는다.** 일반 실행 액션과 cron route 는 두 잡의 `run()` 을 부른다. 이 `run()` 은 이제 적재하지 않고 '조건 창에서 실행하라'며 거절한다. 조건 창은 전용 server action(`runRatioAuditAction`)으로 적재한다. 쿨다운·자동 실행 판정에는 일반 실행과 같은 함수를 쓴다.
5. **대상이 0건이면 적재하지 않는다.** server action 이 적재 전에 같은 대상 함수로 건수를 센다. Moa 로그인 한 번은 사용자 폰에 문자 한 통이고, 대상 없이 17분을 도는 실행이 된다. 적재한 뒤에 0건이 되는 경우(그 사이 마감)는 audit.py 가 로그인 없이 빈 결과를 보고한다.
6. **조건 한 줄** `조건: 2년제 · 수시 · 접수 마감 전 — 대상 N건` 을 두 곳에 적는다. 관리자 메시지에서는 제목 줄 바로 아래, 실행 로그에서는 줄 끝이다. 실행 로그에도 적는 이유는 이상이 0건인 실행에는 관리자 메시지가 아예 나가지 않기 때문이다(`dispatch.ts` 의 nothingToReport). N 은 그 실행이 대상 API 에서 받은 건수다. 문구는 서버가 만들고, audit.py 는 받은 그대로 인제스트에 다시 싣는다(`condition: { requestId, line }`).
7. **대학구분 매핑은 정확히 일치로 본다**(앞뒤 공백만 뗀다). `4년제` → `4년제`, `2년제` → `2년제`·`전문대`. `대학원`·`초중고교`·`기타`·`학위취득`·빈 값은 어느 쪽에도 들지 않는다.
8. **모집구분 규칙의 근거.** 정시 뒤에 붙는 말(가나다·나다·가다·나·다)은 같은 정시 모집의 **군**이다. 반면 수시 뒤의 `재외국민`은 서비스와 경쟁률 세팅이 따로 있는 **별도 전형**이다. 그래서 정시는 접두로, 수시는 정확히 일치로 판정한다. 접두 규칙이 군이 아닌 정시 계열 값까지 끌어오면 사용자 규칙('정시로 시작하는 값 전부')대로 포함한다. 구현할 때 실제 데이터의 distinct 목록을 PR 에 적는다.
9. **표 안의 [지금 실행] 버튼은 다른 잡과 같은 클래스를 쓴다**(공유 상수). 이 버튼만 표준 호버로 바꾸면 한 행만 모양이 달라지고, 다른 잡까지 바꾸면 범위 밖이 된다. 창 안의 새 버튼은 프로젝트 표준(`hover:bg-ink hover:text-cream`)을 따른다.

## 3. 비목표

- 조건 기억·기본값·즐겨찾기, 창 안의 실시간 대상 건수 미리보기
- 다른 잡의 [지금 실행], 자동 스케줄(cron) 등록
- 담당자 개인 메시지에 조건 적기, `ratio_audit_runs` 에 조건 칸 추가(인제스트 payload 에 `condition` 이 들어가므로 이력은 남는다)
- `requested_by` 를 누른 사람의 메일로 바꾸기(지금처럼 `automation` 으로 둔다)
- 큐의 '활성 요청 1건'을 DB 유니크 인덱스로 막기(지금은 조회로만 막는다 — 별건)
- 대학원·초중고교, 편입·재외국민 같은 다른 구분 — 이번에는 4년제/2년제 × 수시/정시만 다룬다
- 폴러 완료 보고(PowerShell 문자열 본문)의 한글 깨짐 — 기존 문제라 이번에 고치지 않는다. 대신 새 실패 줄에는 ASCII 코드를 앞에 붙인다

## 4. 실패로 볼 것

1. 조건을 안 골랐는데(또는 조건 없는 옛 요청으로) Moa 에 로그인한다. 사용자 폰에 문자가 가는데, 무엇을 봤는지 아무도 모른다.
2. 고른 것과 다른 대상을 본다. 수시에 `수시 재외국민`이 끼거나, 정시에서 `정시 가나다`가 빠지거나, 2년제에서 `전문대`가 빠진다.
3. 접수가 끝난 서비스를 다시 보거나, 1~2월에 진행 중인 정시가 빠진다.
4. 결과(관리자 메시지·실행 로그)에 조건이 안 보여서, '검사 0건'이 조건 때문인지 고장 때문인지 구분할 수 없다.
5. 대상이 0건인 조합인데 로그인한다.
6. 다른 잡의 [지금 실행] 동작이나 모양이 바뀐다.
7. 조건 값이 PowerShell 을 지나며 깨져 엉뚱한 대상을 고른다.

## 5. 흐름

```
[자동화 페이지] 지금 실행 ─▶ 조건 창(빈 상태) ─ 대학구분 ≥1 · 모집구분 ≥1 ─▶ [실행]
  └ runRatioAuditAction  (requireAdmin · zod · 자동 실행/쿨다운 판정 = 일반 실행과 같은 함수)
      ├ listRatioAuditTargets(filters, now) ── 0건 → 적재 안 함, 창에 이유 표시
      └ enqueueLocalAuditRequest(automation, now, kind, filters)
            → ratio_audit_requests { kind, filters, status: pending }
            → 실행 로그 "[접수] … 조건: 2년제 · 수시 · 접수 마감 전 — 대상 N건"

[회사 PC poll-local.ps1] GET /api/ratio-audit/audit-request  (claim — 응답 모양은 그대로)
  └ $env:RATIO_AUDIT_KIND = kind ; $env:RATIO_AUDIT_REQUEST_ID = id (ASCII 만 지나간다) ─▶ audit.py

[audit.py] 요청 id 없음 → 로그인 전에 멈춤(exit 1)
  ─▶ GET /api/ratio-audit/targets?requestId=…
       서버: 요청 행 filters → zod (없거나 깨졌으면 409 missing_filters)
             → closing_services write_end_at ≥ now → 대학구분·모집구분 판정
  ◀── { targets, condition: { requestId, line } }
  ├ 대상 0건 → 로그인 없이 빈 결과 인제스트
  └ Moa 로그인 → 목록 전체(시작일 필터 없음) ∩ 대상 → 세팅 순회·판정 / 링크 확인
       ─▶ POST /api/ratio-audit/ingest { kind, …, condition }

[ingest] 관리자 메시지: 제목 줄 아래 condition.line · 실행 로그: 끝에 "(condition.line)"
```

## 6. 배포 순서 (계약이 한꺼번에 바뀐다)

마이그레이션 선적용(사용자가 SQL 실행) → PR 머지·Vercel 배포 → **곧바로** 회사 PC 원래 폴더 `git pull` 순서로 한다. 배포와 `git pull` 사이에는 옛 audit.py 가 요청 id 없이 대상을 부른다. 이때 새 서버가 400 으로 거절해 그 실행은 실패로 기록된다. 로그인 전이라 문자는 가지 않는다. 서버와 폴러를 나눠 내보내면 그 사이 모든 실행이 이렇게 실패하므로 PR 은 하나로 낸다.

## 7. 사용자 확인 필요

1. **대상 0건이면 적재하지 않는다**(결정 5). 사용자 요구에는 없던 동작이다. 권장: 그대로 둔다. 창에 '조건에 맞는 점검 대상이 없어 요청하지 않았습니다 — 2년제 · 정시 · 접수 마감 전'을 보이고, 실행 로그에는 남기지 않는다.
2. **페이지 점검의 '오픈 예정' 포함.** 오픈 전에는 REAL 경쟁률 HTML 이 아직 없을 수 있다. 그렇다면 오픈 예정 서비스마다 404 링크오류가 담당자에게 간다. 지금 규칙(올해 9/1 이후 시작)에도 미래 시작 건이 들어 있어 새로 생기는 문제는 아니지만, 정시가 처음 대상에 든다. 권장: 결정대로 구현한다. 런북에서 페이지 점검을 먼저 **DRY RUN**(발송 없음)으로 돌려 오픈 예정 건의 404 비율을 본 뒤 실발송한다. 404 가 오픈 예정 건에 몰리면, 그때 '페이지 점검만 진행 중으로 좁히는 안'을 제안한다.
