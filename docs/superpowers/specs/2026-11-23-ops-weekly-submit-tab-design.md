# 주간업무보고 — 영역 확인 필수 폐지, `제출` 탭에서 검토 후 제출

## 왜

지금은 다섯 영역(원서접수·합격자 발표·프로젝트·TF·휴가·외근)마다 `[이 영역 확인]` 을 눌러야 `제출완료` 가 켜진다(#1296).
사용자 판단(2026-11-23): 확인 버튼은 *작성* 이 아니라 *절차* 라 운영자에게 직관적이지 않다. 원하는 흐름은

1. 각 영역 탭에서 자동으로 불러온 내용을 보고, 특이사항이 있으면 쓴다
2. 다음 단계에서 앞에서 확인·작성한 내용을 한눈에 다시 본다
3. 최종 제출

## 접근 (사용자 선택: A)

| 안 | 내용 | 장단 |
|---|---|---|
| **A (선택)** | 영역 탭 맨 끝에 `제출` 탭. 영역별 요약 + `제출완료` 버튼이 그 탭에 있다 | 탭 순서가 곧 절차라 '마지막에 제출' 이 화면 구조로 보인다. 요약이 넓은 자리를 쓴다 |
| B | 머리띠 `제출완료` → 검토 모달 | 화면 변경이 적지만 검토가 모달 한 장에 갇히고, 제출 전 검토를 건너뛸 길이 남는다 |

## 설계

**없애는 것**
- `[이 영역 확인]`(`AreaCheckButton`), 영역 탭 라벨 뒤 `✓`, 머리띠 `확인 n/5`, `남은 확인: …`
- 제출 조건 `uncheckedAreas` — 클라이언트(`SubmitBar`)와 서버(`submitReport`) 둘 다
- `markTabChecked` action 과 `AreaNotes` 의 `showCheck` 경로(프로젝트·TF 절 안의 확인 버튼 포함)

**남기는 것**
- DB `ops_weekly_reports.checked_tabs` 컬럼 — 마이그레이션 없이 읽고 쓰지 않을 뿐이다(지난 주 데이터 보존, 되돌리기 쉬움)
- 머리띠의 상태 배지·`제출 n/m · 당번`

**`제출` 탭** (`AREA_TABS` 다섯째 키 `submit`, 주소 `tab=submit`)
- 본인 보고서 화면에서만 보인다. 전체 보고·남의 보고서에는 탭이 없다(제출이 없으므로)
- 영역 넷(원서접수·합격자 발표·프로젝트·TF·휴가·외근)마다 한 묶음:
  - 머리 `원서접수 · 자동 n건 · 직접 n건`(각 탭 제목 줄과 같은 숫자 — 같은 계산 함수를 쓴다)
  - 이번 주 / 다음 주 특이사항 본문, 비었으면 `없음`(흐린 글씨)
  - 프로젝트·TF 는 항목별 `프로젝트명 · 단계` 와 이번 주/다음 주 한 줄씩
  - 묶음 머리를 누르면 그 영역 탭으로 간다(고치러 가는 길)
- 맨 아래 `제출완료`(`HeaderActionButton`) + 기존 대기·결과 문구(`useSubmit` 그대로). 머리띠의 제출 버튼은 없앤다 — 제출 자리는 한 곳
- 제출했거나 제출할 수 없는 상태면 버튼 대신 상태 문구(`제출함 11/23 14:05` 등)
- 이 탭에는 `[특이사항]` 버튼·쓸 것 칸이 없다(프로젝트·TF 탭과 같은 규칙)

**요약의 신선도** — 요약은 서버가 준 `detail`·`snapshot` 으로 그린다. 특이사항 저장이 경로를 다시 그리므로(revalidate) 탭을 옮겨 오면 최신이다 — 구현 때 저장 action 의 revalidate 를 확인하고, 아니면 저장 대기(`pending-saves`)가 끝난 뒤에만 제출되는 기존 장치에 기댄다.

## 검증

- `submitReport` 가 확인 안 한 영역이 있어도 제출된다(서버 테스트)
- 본인 보고서에 `제출` 탭이 있고, 전체 보고·남의 보고서에는 없다
- `제출` 탭이 영역별 건수·특이사항(빈 칸은 `없음`)을 보이고 `제출완료` 를 누르면 제출된다
- `이 영역 확인`·`확인 n/5`·`남은 확인` 문구가 화면 어디에도 없다
