# 어시스턴트 도구 2개 — 운영 데이터 조회와 `제안/` 쓰기

**질문**: 어시스턴트가 읽기만 하고 아무것도 못 하는 상태를, 어디까지 열어야 안전한가.
**날짜**: 2026-08-18

---

## 1. 왜 — 사용자가 짚은 구멍

운영자가 물었다.

> 인수인계 메뉴에 부산대학교 수시 인수인계 내용 업무 지식망에 넣고 싶은데

어시스턴트는 **아무것도 못 했다.** 두 가지가 막혀 있었다.

| 막힌 것 | 왜 |
|---|---|
| 인수인계 내용을 못 읽음 | Claude 모드는 **볼트와 일정 도구만** 본다. 운영 데이터에 닿는 길이 없다 |
| 볼트에 못 씀 | `Write`·`Edit`가 차단돼 있다 (인젝션 방어) |

두 번째는 **의도된 차단**이다 — 볼트는 전원이 쓰는 파일이라 문서 한 줄이 그 PC의 파일 시스템을 여는 경로가 된다. 그래서 범용 쓰기는 계속 막고, **좁은 도구 하나만** 낸다.

---

## 2. 도구 1 — 운영 데이터 검색

### 도메인 하나가 아니라 전부 연다

인수인계만 뚫으면 다음엔 사고 전용, 그다음 연락처 전용을 또 만들게 된다. `searchAllDomains`가 이미 7개를 다루므로 그걸 통째로 노출한다.

```
GET /api/assistant/tools/search?q=<질문>&as=<operator_email>
→ { ok, sources: [{ domain, id, title, snippet, deepLink }] }
```

### 권한 — 조사로 전제가 뒤집혔다

처음에는 "관리자 클라이언트로 갈지, 요청자 권한으로 갈지"를 물었다. **조사해보니 그 대립이 틀렸다.**

7개 테이블의 select 정책이 전부 이렇다:

```sql
for select to authenticated using (true)
```

**로그인한 운영자는 어차피 모든 행을 읽는다.** 클라이언트를 바꿔도 결과가 같다. RLS는 여기서 행을 거르지 않는다.

권한이 갈리는 지점은 **행이 아니라 메뉴**다:

| 대상 | 볼 수 있는 것 |
|---|---|
| admin | 전부 |
| member · viewer | `ADMIN_ONLY_MENU_SLUGS` 6개만 제외 |
| 비운영자 · 탈퇴자 | 없음 |

### 그래서 실제로 거는 검사

```
1. CRON_SECRET 확인                    ← 폴러만 호출
2. as= 이메일로 운영자 조회            ← 없거나 비활성이면 403
3. viewer면 403                        ← 어시스턴트 자체 정책과 일치
4. searchAllDomains 실행
5. 그 사람이 못 보는 메뉴의 도메인 제외
```

**`as=`를 위조할 수 없는 이유**: 폴러는 `CRON_SECRET`을 가진 우리 코드이고, 큐(`assistant_requests`)에서 받은 `operator_email`을 그대로 넘긴다. 그 값의 출처는 **웹 세션**이라 사용자가 만질 수 없다.

### 5번이 지금은 아무것도 안 거른다 — 정직하게 적어둔다

7개 도메인의 사이드바 slug를 실제로 확인한 결과:

| 도메인 | slug | admin 전용인가 |
|---|---|---|
| incident | `incidents` | ❌ |
| handover | `handover` | ❌ |
| ai-tip | `ai-tips` | ❌ |
| backup | `backup` | ❌ |
| contact | `contacts` | ❌ |
| service | `services` | ❌ |
| knowledge | `knowledge` | ❌ |

**하나도 admin 전용이 아니다.** 그러니 5번 필터는 지금 통과만 시킨다.

그래도 넣는 이유는 둘이다.
1. 나중에 어느 도메인이 admin 전용이 되면 **코드를 안 고쳐도** 따라온다
2. 매핑이 틀리면 조용히 결과가 사라지므로 **매핑 자체를 테스트로 고정**한다 — slug가 사이드바에 실재하는지 검사한다. 오타 난 slug는 `ADMIN_ONLY`에 없어서 항상 통과해버린다

**실제로 일하는 것은 2·3번**이다. 지금은 탈퇴자 이메일이 큐에 들어와도 그냥 답한다.

## 3. 도구 2 — `제안/`에만 쓰기

```
propose_doc(title, category, body) → <볼트>/제안/<파일명>.md
```

**API를 거치지 않는다.** 폴러가 이미 볼트 파일에 접근하므로 로컬에서 직접 쓴다. 서버를 왕복시키면 파일이 두 경로로 갈린다.

### 왜 `제안/`만인가

볼트 설계 §7이 이미 정했다 — *"에이전트는 사람 문서를 고치지 않는다. 에이전트가 쓰는 것은 `제안/` 하위에만 들어간다."*

근거는 §8의 실측이다. **에이전트가 쓴 문서 10건 중 3건이 틀렸다.** 근거가 코드에 다 있는 상태였는데도. 검토 없이 쌓이는 경로를 열면 그 오류가 다음 답의 근거가 되고, 다시 쌓인다.

### 지켜야 하는 것 셋

| 규칙 | 왜 |
|---|---|
| 최종 경로가 `제안/` 하위여야 함 | `../`·절대경로·`제안` 접두 위장(`제안-x/`)을 전부 막는다 |
| 같은 이름이 있으면 **실패** | 사람이 검토 중인 초안을 에이전트가 갈아엎지 않게 |
| `Write`·`Edit`는 계속 차단 | 이 도구로만 열고, 범용 파일 쓰기는 막힌 채로 둔다 |

**경로 검증은 순수 함수로 뺀다** (`features/assistant/propose.ts`). 폴러 안에 묻으면 탈출 시도를 테스트할 수 없다.

### 파일명

`title`을 그대로 파일명에 쓰면 `/`·`:` 같은 문자가 경로를 만든다. 정규화한다 — 경로 구분자와 예약 문자를 제거하고, 빈 문자열이 되면 거부한다.

## 4. 파일

| 파일 | 무엇 |
|---|---|
| `api/assistant/tools/search/route.ts` | 신설 — 요청자 검증 + 도메인 검색 |
| `features/assistant/domain-menu.ts` | 신설 — 도메인 ↔ slug 매핑 (순수) |
| `features/assistant/propose.ts` | 신설 — 경로 검증 + 파일명 정규화 (순수) |

| `features/assistant/claude-prompt.ts` | 새 도구를 언제 쓰는지 지침 |

---

## 5. 안 하는 것

| | 왜 |
|---|---|
| 볼트 본 위치에 쓰기 | §7 격리. 사람이 옮긴다 |
| 파일 수정·삭제 | 되돌릴 수 없다. 초안 생성만 |
| 도메인 추가 | 7개로 시작. 필요하면 그때 |
| RLS 재현 | RLS가 행을 안 거른다(§2). 재현할 게 없다 |

---

## 6. 열린 질문

1. **`제안/` 초안이 쌓이면 누가 치우나** — 사람이 옮기지 않으면 그대로 쌓인다. 열람 화면에 `제안/` 건수를 드러낼지
2. **같은 주제 중복 초안** — 에이전트가 두 번 물으면 두 개가 생긴다. 이름 충돌로 두 번째가 실패하는데, 그게 맞는 동작인지
3. **도메인 필터가 지금 무의미하다**(§2) — 어느 도메인이 admin 전용이 돼야 하는지는 운영 판단이다
