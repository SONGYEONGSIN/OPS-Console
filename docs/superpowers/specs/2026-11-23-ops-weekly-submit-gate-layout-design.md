# 주간보고 — 제출 조건·특이사항 열기·프로젝트·TF 탭 (2026-11-23)

## 왜

내 보고서에서 `제출완료` 가 쓸 것 패널 맨 아래에 숨어 있고, 확인을 다 안 해도 눌렸다. 쓸 것 패널은 늘 열려 목록 폭을 먹는다. 프로젝트·TF 는 패널 안 카드 → 서랍이라 한 번 더 들어가야 했다.

## 사용자 결정 (2026-11-23)

1. **제출 조건 = 5개 영역(원서접수·합격자 발표·프로젝트·TF·휴가·외근) 모두 확인.** 화면은 버튼을 끄고 남은 영역을 알려 주며, **서버(`submitReport`)도 같은 조건으로 거부한다.**
2. **제출 버튼은 머리띠 오른쪽** — `작성 중 · 확인 n/5` 뒤.
3. **특이사항은 버튼으로 연다** — 평소 목록이 전체 폭, `[특이사항]` 을 누르면 오른쪽 칸(특이사항·직접 추가)이 열리고 다시 누르면 닫힌다. `[이 영역 확인]` 은 패널 밖, 영역 탭 줄 오른쪽 버튼으로 옮긴다(패널을 열지 않고도 확인할 수 있어야 한다).
4. **프로젝트·TF 는 합격자 발표 옆 영역 탭.** 순서: 원서접수 · 합격자 발표 · 프로젝트·TF · 휴가·외근. 서랍·요약 카드는 없앤다.

## 설계

- `AREA_TABS = application · pims · project · leave`. 탭 `project` 의 라벨은 `프로젝트·TF`, 본문은 프로젝트 절과 TF 절을 위아래로(각자 특이사항·확인 버튼 그대로 — 확인 영역은 여전히 다섯). 주소 `tab=tf` 도 이 탭으로 연다. 탭의 ✓ 는 프로젝트·TF 둘 다 확인했을 때.
- 프로젝트·TF 탭에서는 `[특이사항]`·`[이 영역 확인]` 버튼과 쓸 것 칸이 없다 — 그 탭의 특이사항·확인은 본문 안에 있다.
- 쓸 것 칸은 닫힌 채 시작하고 열림은 화면 상태(주소 아님). 열려도 영역 패널은 모두 마운트된 채라 쓰던 글이 남는다. lg 미만의 `[목록 | 쓰기]` 전환은 같은 버튼으로 대체(열면 목록 위에 쌓인다).
- 제출 버튼: `canSubmit`(상태 규칙) 이면 보이고, 다섯 영역이 다 확인돼야 눌린다. 꺼진 동안 `남은 확인: …` 을 붙인다. 제출 대기·결과 문구는 버튼 아래 그대로.
- 서버: `uncheckedAreas(checked)` 순수 함수 하나를 화면과 `submitReport` 가 같이 쓴다.
- 전체 보고: 프로젝트·TF 탭 본문이 프로젝트·TF 모아보기(아래 따로 있던 절은 없앤다). 쓸 것 칸(사람별 특이사항)도 같은 버튼으로 연다.

## 하지 않는 것

- 확인을 취소하는 기능은 만들지 않는다(지금도 없다).
- 특이사항 작성 여부는 제출 조건이 아니다.
