# 운영부 주간업무보고 — 설계

작성 2026-11-16. 사용자 인터뷰(선택형) + 파일·코드 조사(읽기만) 기반.

이 문서는 **A. 운영부 주간업무보고**만 다룬다. 같은 인터뷰에서 나온 둘은 별도 설계로 뒤따른다.
- B. 본부 주간업무보고(`주간업무보고서_진학어플라이본부_…xlsx`)의 운영부 항목에 A 의 최종본을 자동으로 넣기 — A 의 결과물을 쓰므로 A 다음
- C. 관리자가 프로젝트 새 소식을 영업부에 공유(영업부가 그걸로 대학 뉴스레터를 보낸다) — 독립

## 1. 왜

지금은 운영1·2팀 운영자가 매주 팀 엑셀(`운영부/00. 업무보고(운영부)/주간업무보고_운영1팀.xlsx`·`_운영2팀.xlsx`)에 원서접수 건수와 서술을 손으로 쓰고, 그 주 **차기리더(돌아가며)**가 전체를 워드 한 장(`운영부 주간 업무 보고/운영부 주간업무보고_ YYYY년 M월 N주차.docx`)으로 다시 정리해 팀장·부장님께 메일로 보고한다.

- 원서접수 건수(작업중/테스트/리얼)와 서비스 목록은 **앱이 이미 아는 값**인데 사람이 다시 센다
- 같은 내용을 엑셀 → 워드로 두 번 옮긴다
- 엑셀은 그달 첫 월요일 기준, 워드·본부 파일은 목요일 기준이라 **같은 주를 다른 주차로 부른다**(엑셀 '10월 2주차' = 워드 '10월 3주차')

성공 = 운영자는 미리 채워진 화면을 **확인하고 특이사항만 쓰고 제출**하고, 당번은 워드를 만들지 않고 **확인 후 버튼 하나로 보고**하며, 엑셀·워드는 기록으로 자동으로 쌓인다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 주간보고 페이지(작성·제출·당번 검토·최종 보고)
- 수요일 10:00 작성 요청(메일 + 운영부 그룹채팅방), 목요일 12:00·17:00 미제출자 메일 알림
- 원서접수·PIMS·휴가/외근은 앱 데이터로 미리 채움
- 최종 보고 시 엑셀(팀별)·워드(운영부 1장) 자동 저장

**비목표**
- 원천 데이터 수정: 자동 목록이 틀리면 원래 메뉴(서비스 마감·백업요청 등)에서 고친다. 주간보고에서 '빼기'는 그 주 보고서에서만 뺀다
- 본부 파일 반영(B), 영업부 공유(C)
- 회의 안건 칸: 사용자가 남기지 않기로 함
- 사이트·ARA TF: 다른 부서로 넘어감. 공공접수는 프로젝트가 아니라 원서접수에 포함

**반목표**(기술적으로 돌아가도 실패인 것)
- 담당자 이름이 안 맞아 **본인 서비스가 조용히 빠지는 것**. 매칭 안 된 건수는 화면에 드러낸다(대학배정 `unmatchedVolume` 배너와 같은 원칙)
- 알림 폭탄: 정해진 세 번(수 10:00 / 목 12:00 / 목 17:00)과 상태 전환 알림 외에는 보내지 않는다
- 사람이 쌓아 온 엑셀 과거 시트를 덮어쓰거나 망가뜨리는 것

## 3. 한 주 흐름 (사용자 확정)

| 시점 | 일 | 받는 사람 / 채널 |
|---|---|---|
| 수 10:00 | 그 주 보고서 열림 + 작성 링크 발송 | 운영자 전원 — **메일 + 운영부 그룹채팅방** |
| 수~ | 운영자가 작성 → **[제출완료]** | — |
| 목 12:00, 17:00 | 미제출자에게만 알림 | 미제출 운영자 — 메일 |
| 전원 제출 | 당번에게 알림 | 그 주 당번 |
| 당번 검토 | 운영부 전체 **주요 요약**(금주/차주) 작성, 필요하면 개인에게 **[다시 작성]** 요청 또는 **직접 수정** | — |
| 당번 [최종 보고] | 페이지 링크 발송 + 엑셀·워드 Teams 저장 | 부장·팀장님(관리자 화면에서 지정) — 메일 |

- **작성 대상 = 운영1·2팀 운영자**(`operators.team` 이 운영1팀·운영2팀, 활성 계정). 팀장·부장님은 받는 쪽이라 빠진다(사용자). 이 명단이 제출 분모·알림 대상·당번 후보다
- **전원 제출까지 기다린다.** 마감 시각에 강제로 보내지 않는다(사용자 확정)
- **'제외'나 '대리 제출'은 없다.** 그 주에 휴가인 사람은 **미리 작성**한다(사용자). 그래서 보고서는 수요일 요청보다 먼저 열려 있어야 한다 — 내 판단: 직전 주 최종 보고가 끝나는 순간(늦어도 그 주 월요일 00:00) 다음 주 보고서가 열려 작성할 수 있고, 수요일 10:00 은 '요청 발송'일 뿐이다. 당번의 직접 수정(§4.5)은 그대로라 급할 때 당번이 내용을 채울 수는 있지만 제출은 본인이 한다
- **당번은 순번표로 자동**. 관리자가 그 주만 바꿀 수 있다
- 주차 번호는 **본부·워드 기준**(목요일이 속한 달·주). 본부 잡의 주차 계산(`features/automations/jobs/weekly-report/` 의 isoMonthWeeksCount 계열)을 재사용해 B 와 어긋나지 않게 한다
- 금주 = 그 수요일이 속한 월~금, 차주 = 다음 월~금

## 4. 화면

**배치: 영역별 탭**(사용자 선택). 위에서부터 —

1. **머리줄**: 주차(예: 2026년 11월 3주차 · 11/16~11/20) · 작성자 · 제출 현황 `9/17` · 당번 이름 · **[제출완료]**
2. **건수 카드 6개**(엑셀 건수표 대체): 개발 중 · 테스트 중 · 차주 오픈 예정 · 운영 중 · 차주 마감 예정 · PIMS 발표 예정 — 본인 자동 목록에서 센다
3. **탭**: 원서접수 / PIMS / 프로젝트 / TF / 휴가·외근. 확인한 탭에 ✓

모든 영역에 **영역 특이사항**(금주 / 차주) 칸. 자동 목록이 있는 영역은 **건마다 특이사항**을 달 수 있고, **빼기**(그 주 보고서에서만)와 **직접 추가**가 된다(사용자: 둘 다 적용).

### 4.1 원서접수 (공공접수 포함, 원서접수 외 서비스 칸 포함)
'원서접수 외 서비스'는 자동 목록이 아니라 이 탭의 **직접 추가** 건으로 쓴다(내 판단 — 그런 서비스를 담은 원천이 없다).

**건수 카드는 서로 배타적이지 않다**(내 판단): 카드마다 그 묶음의 건수를 따로 센다. '운영 중'이면서 '차주 마감 예정'인 서비스는 두 카드에 다 들어가고, 합계 카드는 두지 않는다.

본인 담당(`closing_services.operator_name` = `operators.name`) 서비스를 네 묶음으로:

| 묶음 | 기준 |
|---|---|
| 개발 중 / 테스트 중 | Moa `개발 > 작업 통계`(`https://moa.jinhakapply.com/Develop/WorkStatistics`) 대학 검색 결과의 서비스별 개발/테스트 구분(사용자 2026-11-16) — §6.1 |
| **차주 오픈 예정** | `write_start_at` 이 차주 (`closing/next-week.ts` opensNextWeek) — 문구는 '배포 예정'이 아니라 **'오픈 예정'**(사용자 정정) |
| 운영 중 | `closing/phase.ts` phaseOf === "running" |
| 차주 마감 예정 | **접수 마감** `write_end_at` 이 차주(사용자 확정, 결제 마감 아님) |

### 4.2 PIMS
본인 담당 `announcement_services` 중 발표일(`last_announce_at`)이 금주·차주인 건(사용자: 발표 서비스 목록 기준). 담당자 매칭이 87곳 중 58곳뿐(조사 시점)이라 매칭 안 된 건수를 드러낸다.

### 4.3 프로젝트 · TF
- **목록 = 사이드바 '프로젝트' 묶음**: PIMS · 접수관리자 · 내부관리자 · 경쟁률 · 생성툴 · 매출 분석 · 정산·진학캐쉬 · 초중고 · 인증 · 대교협 연계 · 추천인 검증 · 보증보험 · 실적증명 + **계약서 · 유의사항 추가**(사용자). 메뉴 페이지들은 지금 예시 데이터(비활성)다 — 이번에 페이지를 살리지는 않는다
- 관리자가 주간보고 설정에서 항목을 더하고 담당자를 지정한다. **TF 는 같은 목록의 한 종류**(구분 = 프로젝트/TF), 화면에서는 TF 탭에 따로 나온다
- 운영자는 본인 담당 항목마다 **진행 단계 · 금주 · 차주 · 그림 붙여넣기**. 지난주 값이 미리 채워진다
- **한 항목을 여럿이 맡으면 각자 쓴다**(사용자) — (항목, 운영자) 단위. 최종 보고·워드에서는 항목 아래 담당자별로 묶어 보여 준다
- **진행 단계는 소프트웨어 개발 단계(SDLC) 기반 8개로 고정**(사용자 2026-11-16): **기획 · 요구분석 · 설계 · 개발 · 테스트 · 배포 · 운영 · 보류**. 세부 구분은 두지 않는다(관리자가 따로 나누지 않음 — 사용자). 앞선 7단계 초안은 표준이 아니어서 버렸다
- 그림 붙여넣기는 **프로젝트·TF 에만**(사용자). 체크리스트의 붙여넣기(`app/r/checklist/[token]/_components/RichNote.tsx` onPaste + `features/checklist/fill-actions.ts` 5MB·Storage)를 재사용

### 4.4 휴가 · 외근
금주·차주에 걸친 본인 **백업요청**(`backup_requests` — 휴가/외근 유형·기간·백업자)과 **일정**(`schedule_events` 휴가·외근)을 합쳐 중복을 지우고 보여 준다(사용자 확정). 빠진 건은 직접 추가. 백업자가 없는 휴가에는 **[백업요청 만들기]**(백업요청 화면으로 이동).

### 4.5 당번 화면
제출 현황 표(운영자별 제출/미제출/다시 작성 요청) · 운영부 **주요**(금주/차주) 요약 입력 · 운영자별 보고서 열람·직접 수정 · **[다시 작성]**(그 운영자를 미제출로 되돌리고 알림) · **[최종 보고]**(전원 제출일 때만 켜짐).

### 4.6 열람·권한
- 운영부 전원이 서로의 보고서를 **본다**. 수정은 본인 것만(사용자)
- 당번은 그 주 동안 전원 것을 수정할 수 있다
- 관리자: 설정(받는 사람·순번표·프로젝트 목록) + 당번 변경
- 가드는 `requireMenu(slug)` 하나 + server action 에서 본인/당번/관리자를 DB 로 다시 판정(폼 값을 믿지 않는다 — 오픈안내 탭과 같은 원칙)

## 5. 최종 보고 산출물

- **메일**: 받는 사람 = 관리자 화면에서 지정한 부장·팀장님. 내용 = **페이지 링크**(사용자 선택: 링크만). 브랜드 문구는 `[운영부 상황실]`
- **받는 분은 OPS-Console 에 로그인해서 본다**(사용자 — 토큰 공개 링크 아님). 그래서 받는 사람으로 지정된 계정은 주간보고 메뉴를 볼 수 있어야 한다 — 설정 화면이 메뉴 권한 없는 사람을 고르면 경고하고, 권한 부여는 기존 운영자 권한 관리로 한다
- **보고하면 그 주 보고서는 잠긴다**(내 판단): 링크가 가리키는 내용 = 엑셀·워드에 저장된 내용이어야 해서다. 관리자가 '정정'으로 풀어 고치면 엑셀·워드를 다시 저장하고, 메일은 다시 보내지 않는다
- **엑셀**: 팀별 파일(`주간업무보고_운영1팀.xlsx`·`_운영2팀.xlsx`)에 그 주 기록을 남긴다. 양식은 페이지에 맞게 바꿔도 된다(사용자). 기존 월 시트는 건드리지 않는다
- **워드**: `운영부 주간 업무 보고` 폴더에 `운영부 주간업무보고_ YYYY년 M월 N주차.docx`(본부 기준 주차) 1개. 양식 변경 가능. 지금 한 장짜리 표(구분/금주/차주 — 주요·기본·기타)를 출발점으로 영역별 행으로 늘린다

## 6. 구현 결정 · 제약

### 6.1 개발/테스트 구분 수집
- Moa 는 2FA(SMS) 로그인이다. 새 로그인을 만들지 않고 **이미 매일 도는 회사 PC Moa 스크랩**(`scripts/moa-closing/`)에 WorkStatistics 수집을 붙여 서비스별 구분을 적재한다 — 로그인 1회에 얹어야 인증 문자가 늘지 않는다(SMS 우편함 리스 규칙은 CLAUDE.md 그대로)
- 결과는 서비스ID 기준 표에 `구분 · 수집 시각`으로 둔다. 주간보고는 읽기만
- 그 주에 수집이 안 됐거나 매칭 안 된 서비스는 **'구분 미확인'** 으로 보여 준다(0 으로 숨기지 않는다)
- 화면 구조(열 이름, 대학 검색 방식, 서비스ID 노출 여부)는 **미확인** — 구현 첫 단계에서 사용자 승인을 받아 1회 로그인해 확인한다
- **이 수집은 별도 PR 로 뒤에 붙여도 된다**(내 판단): 수집이 없으면 개발 중·테스트 중 두 카드와 묶음이 '구분 미확인'으로 나오고 나머지는 그대로 동작한다. 일일 마감 스크랩과 SMS 리스에 얹히는 변경이라 주간보고 본체와 위험을 분리한다

### 6.2 발송
- 메일은 Graph sendMail(`lib/microsoft`), Teams 는 기존 자동화 발신 계정(`TEAMS_AUTOMATION_SENDER` 계열)
- 운영부 그룹채팅방 = Teams 그룹채팅 **'운영부 마법사'**(사용자 2026-11-16). chat id 는 env 로 받는다(신규 — 본부 잡의 `TEAMS_CHAT_ID` 는 본부 방이다). id 는 구현 때 Graph 로 그 이름의 채팅을 찾아 확인하고, 발신 계정이 그 방의 멤버인지도 함께 확인한다(멤버가 아니면 못 보낸다)
- `…_DRY_RUN=true` 면 발송 없이 이력만(기존 메일 기능과 같은 안전장치)
- 수 10:00 / 목 12:00·17:00 는 자동화 레지스트리 잡 + cron-job.org(다른 잡과 같은 경로). **등록이 코드 밖에서 끝나므로** 머지 후 등록 확인을 체크리스트에 넣는다
- 발송 결과는 `recordAutomationRun` 으로 남겨 실패 즉시 알림·일일 보고에 잡히게 한다

### 6.3 엑셀·워드 저장
- 엑셀은 사람이 같은 파일을 열어 둘 수 있다 — 통째로 내려받아 덮어쓰지 말고 Graph workbook API(`lib/microsoft/workbook-session.ts`)로 새 시트·범위만 쓴다
- 저장 실패가 보고 발송을 막지 않는다. 실패는 당번 화면과 자동화 실패 알림에 드러낸다

### 6.4 공통
- 날짜·시각은 `kstFormat`, 색은 토큰(디자인 시스템 규칙)
- 운영자 팀 소속은 `operators.team`
- 새 테이블은 RLS + `is_admin()` 감싸기 규칙. DB 변경은 마이그레이션을 머지 전에 사용자가 적용
